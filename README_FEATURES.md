# Возможности ImageProcessor

## Основной пайплайн

Скачивает картинки (по списку URL) или берёт локальные → удаляет фон через нейросеть rembg → масштабирует → накладывает на твой фон → сохраняет PNG. Всё в три параллельных этапа: download → process → save.

## GUI

### Drag-and-drop
Левая верхняя зона принимает:
- **`links.txt`** — пакетный режим со скачиванием (формат описан в `README_BUILD.md`)
- **Одну или несколько картинок** — обработка локальных файлов

При дропе картинок имя art-папки берётся из имени родительской папки (либо `images` если её нет).

Вторая зона — для фона. Туда дропаешь любое изображение.

### Режимы выбора модели

- **AUTO** — программа считает среднюю яркость каждой картинки и выбирает:
  - яркость > 200 → `u2net` (для светлых фонов)
  - иначе → `isnet-general-use`
- **MANUAL** — берётся модель из выпадающего списка

### Доступные модели

В выпадающем списке: `u2net`, `isnet-general-use`, `birefnet-general-lite`, `silueta`, `isnet-anime`. Все модели rembg поддерживаются — в combobox можно ввести любое имя руками (например, `u2netp`, `u2net_human_seg`, `sam`).

### Прогресс по этапам
Три отдельных progressbar:
- **Download** — сколько скачано
- **Process** — сколько прошло через rembg
- **Save** — сколько финальных PNG записано на диск

Видно где затык: сеть, GPU/CPU или диск.

### Превью результата
Справа в окне — миниатюра последнего сохранённого PNG. Видно сразу, что обработка идёт правильно, а не генерирует мусор.

### Stop-кнопка
STOP корректно дочищает уже взятые задачи и встаёт. Окно не закрывает, состояние не теряет. Новые задачи не берутся.

### Сохранение настроек
Всё сохраняется в `%APPDATA%\ImageProcessor\config.json`:
- размер окна
- последний путь output
- выбранная модель и режим
- все параметры из Settings

При следующем запуске всё подтягивается.

### Settings-диалог
Кнопка **Settings...** — окно где настраивается:
- число воркеров на каждый этап (`download_workers`, `process_workers`, `save_workers`)
- `max_input_size` — до какого размера ужимать вход для rembg (меньше = быстрее, больше = точнее края)
- `upscale_factor` — коэффициент апскейла после удаления фона
- `bg_width` × `bg_height` — размер фонового полотна
- `retry_attempts` — сколько раз пытаться скачать одну картинку
- `retry_delay` — базовая задержка между попытками (растёт экспоненциально: 1с → 2с → 4с)

Кнопка **Reset to defaults** возвращает заводские настройки.

## CLI-режим

Если передать `--links` или `--images`, GUI не запускается — всё идёт через консоль:

```cmd
ImageProcessor.exe --links links.txt --bg bg.jpg --output out\
ImageProcessor.exe --images photo1.jpg photo2.jpg --bg bg.jpg --output out\
ImageProcessor.exe --images C:\photos\folder --bg bg.jpg
ImageProcessor.exe --links links.txt --bg bg.jpg --model u2net
```

Параметры:
- `--links FILE` — путь к links.txt
- `--images FILE [FILE ...]` — отдельные файлы или папки (папки разворачиваются автоматически)
- `--bg FILE` — фон (обязателен в CLI)
- `--output DIR` — куда складывать (если не указан, берётся из конфига)
- `--model NAME` — `AUTO` или конкретная модель

`Ctrl+C` корректно останавливает обработку (как кнопка STOP в GUI).

## Retry для скачиваний

По умолчанию 3 попытки с экспоненциальной задержкой (1с, 2с, 4с). Настраивается в Settings. Раньше один таймаут означал потерю картинки навсегда.

## Идемпотентность

Программа помнит, что уже обработано — в `output/processed.txt` хранится список ключей. Если запустить тот же links.txt повторно, уже обработанные ссылки пропускаются. Если хочешь переобработать — удали `processed.txt`.

## Различия CPU vs GPU версий

Поведение одинаковое, отличается только скорость и заголовок окна.

GPU-версия:
- Заголовок окна: `Image Processor — GPU (CUDA)`
- В лог при старте пишет какой провайдер активен
- Если CUDA не найдена — fallback на CPU и предупреждение в логе

CPU-версия:
- Заголовок окна: `Image Processor`
- Никаких CUDA-проверок

## Что я починил в исходном коде

1. **Tkinter из потоков.** В оригинале фоновые воркеры писали в `Text` и `Progressbar` напрямую. В чистом Python почти всегда работает, но в собранном exe регулярно даёт `RuntimeError` или молчаливые краши. Теперь все обновления GUI идут через `root.after(0, ...)`, как и положено.
2. **Гонка при создании rembg-сессии.** `new_session` мог вызваться двумя процессорными воркерами одновременно для одной модели → лишние загрузки/повреждённый кэш. Добавил `session_lock`.
3. **Гонка при записи `processed.txt` и `errors.log`.** Добавил локи на запись.
4. **START кнопка пропадала при не-fullscreen.** `Text` с `expand=True` выдавливал её за границу окна. Теперь кнопки прибиты к низу через `side="bottom"`.
5. **`sys.stdout`/`stderr` = None в windowed-режиме.** При сборке с `--noconsole` они становятся `None`, и любая внутренняя библиотека, которая попробует что-то напечатать, упадёт. Добавил заглушку.
6. **Ранний выход при пустом списке задач.**
